00

How to read this

This is a specification, not a pixel comp. It tells you what each screen is for, what data it shows, and how it behaves — then leaves the visual execution to the design language.

Inherits the design language
Every token, font, and primitive comes from the Hatchly design-language file. Nothing here redefines color, type, or motion — it composes the existing Button, Card, PhaseBadge, ScoreRing, etc.
One object, one agent
The whole app is one Idea record that accumulates state, and one phase-aware chat agent that reads it. Phases are views over that growing state — not separate apps. Keep this in mind on every screen.
Locked & empty states matter
Most tabs exist in every phase but unlock progressively. Each screen spec calls out its locked state (gate not yet met) and empty state (unlocked, no data) — these are first-class, not afterthoughts.
Scope locked for v1
Desktop-first. Marketing = landing + how-it-works. New ideas open straight into the chat (no form). The all-ideas board carries a smart insights strip. Connections are account-level. Mobile is a later pass.
01

The lifecycle

Hatchly carries an idea from a sentence to a running business across four phases. The first three are the design-language spine; the fourth is an operating mode after launch.

Ideation
Shape it
Chat captures the idea, builds tagged memory, fills the rubric.
Validation
Pressure-test it
Score the 13 dimensions, generate the report, run action items.
Launch
Ship it
Archetype playbook becomes a real task board: legal, payments, ops.
Post-launch
Run it
Chat becomes the standing advisor and source of truth.

Phase color contract. Ideation = amber (--accent-soft), Validation = info, Launch = success, Post-launch = neutral surface. This preserves "one accent" — post-launch deliberately gets no brand color because the work there is steady operation, not a milestone.

Gates between phases

Ideation → Validation
Opens when the rubric reaches a completeness threshold — N of 13 dimensions have enough signal in memory.
Validation → Launch
Opens when validation action items are complete and the business archetype is confirmed.
Launch → Post-launch
Opens when the launch board's blocking tasks are done (or the user marks "we're live").

BrandBucket — earned, never pushed

Hatchly is a standalone product; BrandBucket is inventory injected at the right moment, not a storefront. Domain suggestions surface only on the Brand tab, only once the idea has a clear shape (positioning + ICP scored), framed as "names that fit what you're building." The agent already knows the phase and signal, so it knows when a suggestion is help versus an ad. Two earned moments: late validation (naming becomes relevant) and the launch unlock (a name is required to proceed).

03

The workspace shell

Every idea screen lives in one three-column frame. The shell is constant; only the middle column changes with the active tab.

Left · sidebar
Back-to-ideas, idea name + score, the phase tracker (Ideation ✓ → Validation ● → Launch 🔒 → Post-launch 🔒), then the flat nav. Settings pinned bottom. Width ~200px. Extensible — new destinations append to the nav list.
Middle · tab view
The active tab's content. Fills remaining width, scrolls independently. This is the only column that changes between Overview / Memory / Scorecard / Plan / Brand.
Right · chat (collapsible)
The persistent phase-aware agent. Multimodal input (text · link · voice). Width ~320px, collapses to a 44px rail. Default open in Ideation/Validation, default collapsed in Launch/Post-launch.

Shell behavior

Phase tracker
Doubles as the gating UI. Completed phases show a check, current is filled, future phases show a lock. It is read-only — phase only advances when a gate is met.
Nav lock states
Tabs mirror the phase. In Ideation, Scorecard and Brand are greyed/locked; they light up as their gates clear. Lock icon + tooltip explaining what unlocks them.
Chat default
The agent sets the sensible open/collapsed default per phase; the user can override and the choice persists per idea.
Header context
Idea one-liner sits at the top of the middle column; name + score live in the sidebar so they persist across tabs.

Overlays & detail screens

Open within the workspace as drawers or modals — they never navigate away from the idea.

Task detail · drawer
Slides in from right. Full description, subtask checklist, status, category, vendor suggestions, linked resources, comments/agent notes. slide-in motion.
Memory source · viewer
The original input behind a memory — chat turn, fetched link content, or voice transcript — with the extracted memory highlighted.
Validation report generation
The Ideation→Validation moment. Agent scores all 13 dimensions with a staged reveal (rings filling, count-ups). Creates the first ScorecardSnapshot.

Validation→Launch transition. Confirms business archetype, then instantiates the playbook into the Plan board. Celebratory but calm.

A DomainSuggestion expanded: name, price, why it fits, and the BrandBucket acquire handoff. The one place money changes hands with the partner.
Idea settings · modal
Rename, edit one-liner, set/change business archetype, archive, delete. Archetype change can re-derive launch tasks.

10

The phase-aware chat

One thread, but the agent's system prompt and tools change with the idea's phase. This is what makes the product feel like a partner rather than a tracker.

Tool set by phase

PhaseAgent's jobTools (write side effects)
IdeationInterview-as-conversation; fill the rubricsave_memory · tag_memory · fetch_link · transcribe_voice · update_idea_field · assess_completeness
ValidationHonest assessmentscore_dimension · generate_snapshot · create_action_item · adjust_task · complete_task
LaunchOperational guidanceconfirm_archetype · instantiate_playbook · create_task · split_task · suggest_vendor · suggest_domain
Post-launchStanding advisor / source of truthretrieve_context · save_memory · create_task · advise
Completion detection
The agent can mark a task done from conversation ("the landing page is live, got 12 pre-orders"), complete the Task, write a Memory, and re-score — not just react to checkbox clicks. This is the magic moment; it is also the riskiest loop to get right and should be prototyped first.
Honest scoring
The scoring agent's contract is "assessment, not encouragement." It must be willing to score a dimension at 58. Test against deliberately weak ideas — a flatterer makes the whole product worthless.
Reference resolution
Because the idea's structured state is in context every turn, "the distribution problem" resolves to dimension 13 and "that task" to a real Task id — no transcript re-reading.
Launch = playbook, not freeform
Launch tasks are instantiated from an archetype PlaybookTemplate and customized — never invented from scratch each time. This is the difference between reliable and hallucinated.

Build notes

Scope and sequencing guidance for whoever builds this.

Desktop-first
The 3-column shell is a desktop layout. Mobile is a later pass: sidebar → drawer, chat → bottom sheet, middle column full-screen. Don't squeeze three columns into a phone.
Prototype the risky core first
The unproven part is the ideation extraction + scoring loop (messy chat → tagged memory → stable scores). Validate that headless before polishing UI — the report, board, and playbooks are downstream and comparatively easy.
Reuse the primitives
Everything composes existing components from src/ui.jsx. No new color, type, or motion. If a screen seems to need a new primitive, check the inventory first.
Demo with the seed
The §12 dataset is built to walk a demo through all four phases on three ideas. Load it as fixtures so every screen has real content from first paint.
